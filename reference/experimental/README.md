# Experimental polarization curves

Measured polarization curves from the literature, used for *benchmarking* — how
closely a model reproduces a real cell. This is a different question from
verification, and the expected answer is a discrepancy, not agreement.

> **Nothing here is generated by this repository.** These files are inputs, and
> they are committed for the same reason the MATLAB reference is: a benchmark
> result is meaningless if the data it was measured against can change without
> a trace.

## Every file needs a citation, in this table

A curve with no recorded source cannot be used in the thesis. Add a row when a
file is added; write a new row rather than editing an old one when a file is
replaced.

| File | Full citation | Figure / table | Cell and conditions | How digitised | Date added |
|---|---|---|---|---|---|
| _(TODO: no curves stored yet)_ | | | | | |

- **Full citation** — authors, title, journal, volume, pages, year, DOI. Enough
  to appear in the bibliography as it stands.
- **Figure / table** — exactly where in the publication the points come from,
  e.g. *Fig. 6(a), open symbols, 80 °C case*.
- **Cell and conditions** — active area, temperature, pressures, humidities,
  stoichiometries, membrane and GDL where the source states them. A model cannot
  be pointed at a curve whose operating conditions are unknown, so anything the
  source does not state must be written down as unknown rather than assumed.
- **How digitised** — the tool used if the points were read off a printed
  figure, and the estimated reading uncertainty. A digitised curve carries an
  error of its own, and a benchmark RMSE below that error is not a meaningful
  number.
- **Date added**.

## Copyright

Digitising a published figure reproduces someone else's data. Store only what
the comparison needs, always with the citation above, and treat the numbers as
quoted from the source rather than as data of mine.

## File format

The same two-column CSV the MATLAB reference curves use, ascending in current
density, with `#` comment lines carrying the provenance into the file itself:

```csv
# Author et al. (year), doi:..., Fig. N, <conditions>
# digitised with <tool>, <date>, reading uncertainty ~<value> V
current_density_A_cm2,voltage_V
0.0500,0.8400
```

| Column | Meaning |
|---|---|
| `current_density_A_cm2` | current density [A/cm²] |
| `voltage_V` | cell voltage [V] |

If the source reports current in A and an active area separately, do the
division when producing the file and record the area used in the table above.

## Conditions must match the case

A case file that names an experimental curve should state the operating
conditions of *that measurement* in its `params` block. Benchmarking a model run
at 70 °C against a cell measured at 80 °C measures the mismatch in the
conditions, not the model — so the case file, not this directory, is where the
two are tied together.
