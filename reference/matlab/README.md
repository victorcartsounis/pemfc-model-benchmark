# MATLAB MMM1D reference outputs

This directory holds outputs computed with the MATLAB reference implementation
of the two-phase MEA model, stored so that my Python solver can be verified
against them without MATLAB being installed.

> **Nothing here is generated by this repository.** These files are inputs. They
> are committed, unlike everything under `results/`, because they are the fixed
> standard my code is checked against and a verification result means nothing if
> the reference can silently change underneath it.

## Reference implementation

The stored outputs come from the reference implementation published with:

> R. Vetter, J. O. Schumacher, *Free open reference implementation of a
> two-phase PEM fuel cell model*, Computer Physics Communications **234** (2019)
> 223–234. <https://doi.org/10.1016/j.cpc.2018.07.023>

Source code: <https://github.com/Isomorph-Electrochemical-Cells/PEMFC-1DMMM>

That paper defines the model formulation and the parameter values; cite it for
the physics. It is the standard I am checking against, and its authors are not
the owners of the code in this repository, which is my own work.

## What every file in this directory must record

No file is usable as a reference unless the table below can be filled in for it.
Add an entry here whenever a file is added, and do not remove one when a file is
replaced — write a new entry instead, because a verification result in the
thesis refers to a particular export.

| File | MMM1D revision | Script / how run | Parameters and conditions | Solver tolerance | Date | Notes |
|---|---|---|---|---|---|---|
| _(TODO: no exports stored yet)_ | | | | | | |

The columns are what makes a number reproducible:

- **MMM1D revision** — the exact commit of the upstream repository. A tag or
  release name is not enough on its own.
- **Script / how run** — the driver script or command used, including any edits
  made to the upstream code. If the upstream code was modified, say how; an
  unrecorded edit makes the reference unrepeatable.
- **Parameters and conditions** — the parameter set and operating point. For a
  verification case this must be identical to what the matching case file in
  `cases/` states, which is the whole basis of the comparison.
- **Solver tolerance** — the tolerance MATLAB's `bvp4c` ran at. The verification
  tolerances in the case file should be justified against this number, not
  chosen for convenience.
- **Date** — when the export was produced.

## File format: profiles

A long (tidy) CSV, one row per point, with exactly these columns:

```csv
layer,variable,x_um,voltage,value,unit
AGDL,T,0.0,0.75,343.15,K
```

| Column | Meaning |
|---|---|
| `layer` | one of `AGDL`, `ACL`, `PEM`, `CCL`, `CGDL` |
| `variable` | one of `phi_e`, `phi_p`, `T`, `lambda`, `wH2O`, `wO2`, `s`, `Pgas` |
| `x_um` | position in µm, from the anode GDL / gas channel face |
| `voltage` | cell voltage [V] of the operating point |
| `value` | the variable, in the unit below |
| `unit` | `V`, `V`, `K`, `-`, `-`, `-`, `-`, `Pa` respectively |

Three constraints the loader enforces, and why:

1. **A row's `variable` must be defined on its `layer`.** Oxygen has no meaning
   in the anode GDL. A row placing it there means the two codes are not
   describing the same problem, which is exactly what verification should catch,
   so it is an error and not a warning.
2. **Each layer is stored separately, and positions do not need to match my
   mesh.** The profiles are genuinely discontinuous at the four internal
   interfaces: each interface position is the last point of one layer and the
   first of the next, holding two different values. Keeping the layer in its own
   column means nothing has to guess which of the two a row is. My solver is
   interpolated onto these positions at comparison time.
3. **Saturation is stored as the saturation `s` [-], not as a liquid pressure.**
   Both codes solve for the liquid water pressure and invert the
   capillary-pressure curve to get `s`; storing `s` keeps the comparison in the
   quantity the literature plots. If an export gives `P_liq` in Pa instead,
   convert it when producing the file and say so in the notes column.

## File format: polarization curves

A two-column CSV, ascending in current density. Lines beginning with `#` are
skipped, so the provenance can travel inside the file as well as in the table
above:

```csv
# MMM1D <commit>, <script>, bvp4c tol = <value>, exported <date>
current_density_A_cm2,voltage_V
0.0512,0.9000
```

| Column | Meaning |
|---|---|
| `current_density_A_cm2` | current density [A/cm²] |
| `voltage_V` | cell voltage [V] |
